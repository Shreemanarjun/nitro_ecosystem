# Typed-data fields in records

How a `Uint8List` (or any other typed list) field of a `@HybridRecord` reaches
Dart, what it cost, and what changed. The wire format is unchanged ([wire_format.md](wire_format.md)).

## What it cost (0.8.8)

A body returned inside a record was copied on every hop:

| Backend | Copies in native code | Then in Dart |
|---|---|---|
| C++ | 2: `writeBytes` into the writer's vector, `toNative` into a second block | 1: `readBlob` → `sublist` |
| Swift | 3: `Array(v)`, `append`, `toNative` | 1 |
| Kotlin | 4: `out.write`, `toByteArray`, `lenBuf.array() + payload`, JNI `GetByteArrayRegion` | 1 |

The Dart copy is the expensive one, about two thirds of the total. A `sublist`
of a large field costs roughly five warm `memcpy`s, because it lands in a freshly
allocated Dart-heap object every call. At 1 MiB: Dart `sublist` 113 µs, C++ write
20 µs, C++ frame 19 µs.

## What changed

Two independent changes.

**1. The C++ writer builds the record in the block Dart receives.**
`NitroRecordWriter` holds one `malloc`'d `[4B length][payload]` block instead of
a `std::vector`, and a record's `toNativeBuffer()` hands that block over
(`takeNativeBuffer()`). One copy fewer for every record and variant, with no
change to specs or to Dart.

**2. The Dart reader lends the record's buffer to a typed-data field.**

When Dart owns the record's buffer (method returns, `@nitroNativeAsync` results,
stream items), the reader returns the field as external typed data over the
buffer and the generated `_nitroFree` skips that buffer. It applies to every
typed-list field (`Uint8List`, `Int16List`, `Float32List`, `Float64List`, …) of
every `@HybridRecord` on every backend, with no annotation: the buffer is
`malloc`'d by the bridge whoever produced the bytes.

A list wider than a byte needs an aligned address and the wire does not pad. When
the field is off the boundary the reader slides it back by up to 7 bytes inside
the buffer, over bytes it has already decoded (the field's own length and the
frame prefix alone are 8). That is one in-place move instead of a copy into a
new Dart-heap object; when the field already sits on the boundary nothing moves.

Rules the reader enforces:

- Fields under `RecordReader.lendMinBytes` (8 KiB) are copied. Handing a buffer
  to a list costs about 0.15 µs, which copying beats below roughly 4 KiB; at
  8 KiB lending is 9% faster and the gap widens with size (measured).
- One field per record is lent. A second large field is copied, since it would
  need the first one's lifetime.
- Only an owned buffer is lent. A `@NitroResult` payload (pointer inside the
  result blob), list items and callback arguments are copied as before.
- Web copies (`readBlobView` falls back to `readBlob`).

A module with no typed-data record field generates the same Dart as 0.8.8. Code
generated by 0.8.8 keeps copying on the new runtime until it is regenerated.

## Who frees the buffer

The module does, through a new export next to `<lib>_nitro_free`:

```c
NITRO_EXPORT void <lib>_nitro_adopt(void* list, void* ptr, intptr_t size);
```

It registers a finalizable handle (`Dart_NewFinalizableHandle_DL`) on the list:
the buffer is freed when the list is collected, in whichever isolate of the
group that happens.

Not `asTypedList(finalizer:)`. dart:ffi frees such memory when the isolate that
created the list exits, so a list that is the **result of `Isolate.run` /
`compute`** (handed over with `Isolate.exit`) points at freed memory:

```dart
final list = await Isolate.run(() => malloc<Uint8>(64).asTypedList(64, finalizer: malloc.nativeFree)..fillRange(0, 64, 7));
print(list[0]); // not 7
```

`@zeroCopy` typed-data returns had exactly this problem and now use the same
mechanism (`<lib>_nitro_adopt_typed_data_return`). The handle is also cheaper:
0.10 µs per list against 0.27 µs for the dart:ffi finalizer.

`tool/verify_record_lend.dart` checks it against the export as generated: lists
of 16 bytes to 4 MiB returned from `Isolate.run` stay intact with nothing freed,
and 505 dropped lists are freed by the collector. It also prints what
`asTypedList(finalizer:)` does in the same position ("already freed").

To switch lending off, in the isolate that decodes:

```dart
RecordReader.lendMinBytes = 1 << 62; // never lend
```

## Measured

AOT, macOS arm64, C++ module returning `{String title; Uint8List body}`; each
cell is the median of 3 processes × 11 rounds, in ns per call. "Detached" is
nitro_http's hand-written address/length/owner hand-off.

| Body | Produce only | 0.8.8 | C++ writer change only | Both changes | Detached |
|---|---|---|---|---|---|
| 256 B | 32 | 230 | 210 | 216 | 620 |
| 4 KiB | 68 | 588 | 481 | 490 | 665 |
| 8 KiB | 135 | 921 | 791 | 672 | 676 |
| 16 KiB | 256 | 1 578 | 1 305 | 959 | 848 |
| 64 KiB | 1 229 | 7 956 | 8 374 | 3 120 | 2 241 |
| 256 KiB | 4 601 | 50 723 | 46 997 | 24 117 | 8 145 |
| 1 MiB | 17 658 | 192 020 | 155 138 | 51 250 | 43 118 |
| 16 MiB | 274 063 | 2 724 125 | 2 238 250 | 707 563 | 311 250 |

Peak memory for one body: 0.8.8 4× the body, C++ writer change only 3×, both
changes 2×, detached 1×.

"C++ writer change only" is what a lent field is not: a field under 8 KiB, a
second large field, another typed list, or lending switched off. It moves with
the allocator: in a tight loop on macOS it is between 25% slower (64–96 KiB) and
2.3× faster (48 KiB) than 0.8.8 depending on which size class the blocks fall
in. "Both changes" is faster than 0.8.8 from 8 KiB up and at least 2× faster
from 64 KiB up in every run.

A `Float64List` field, same harness (ns per call):

| Field | 0.8.8 | Branch, moved in place | Branch, already aligned |
|---|---|---|---|
| 16 KiB | 1 592 | 1 206 | 952 |
| 64 KiB | 8 028 | 7 054 | 3 054 |
| 1 MiB | 190 566 | 65 559 | 51 842 |
| 16 MiB | 2 714 000 | 1 095 750 | 712 813 |

Peak memory for a 16 MiB list: 4× → 2×.

On Linux (glibc, g++ 12, arm64 VM) the C++ side alone — fresh body, encode, copy
out, free — is never slower: 1.03× to 5.1× faster from 256 B to 4 MiB.

Not timed: phones and Windows. The type-coverage suite passes on an iPhone 12 and
on the Android emulator with every typed-data field lent.

## Not built: an external blob on the wire

The remaining gap to "detached" is the one copy into the record block
(16 MiB: 0.44 ms against 0.04 ms over producing the body) and 2× memory instead
of 1×. Closing it means the record carries a pointer instead of the bytes:

```
[int32 -1][int64 address][int64 length][int64 owner][int64 release_fn]
```

with a C++ `writeBytes(std::vector<uint8_t>&&)` that moves the vector out. It was
left out because a record that carries a pointer has to be decoded exactly once
by a reader that adopts it. Today a record buffer can be dropped undecoded (a
stream with `dropLatest`, a `LazyRecordList` item never read, an isolate that
goes away) and `free` is enough; with a pointer inside, each of those leaks the
body unless every drop site learns to walk the record. nitro_http handles this
by hand (`DetachedBody`). It only helps C++ engines that already hold the bytes
in a movable container; Swift `Data` and Kotlin `ByteArray` still need one copy.

## Breaking for hand-written C++

`NitroRecordWriter::_buf` is gone and the writer is no longer copyable. Code that
took the payload with `std::move(w._buf)` reads it through `w.toBuffer()`
(`{data, size}`, valid while the writer lives). The struct sits in an inline
namespace (`nitro_writer_v2`) so that a plugin generated before this change can
be linked into the same binary: with shared names the linker kept one copy of
each member function for both layouts, which crashed at `-O0` and `-Os`.

## Changelog entries, for the release that carries this

Not in the changelogs yet: their top heading must equal the pubspec version, and
0.8.8 is published.

nitro:

- **Perf:** a typed-data field (`Uint8List`, `Float32List`, …) of a returned `@HybridRecord` is a view of the record's buffer, not a copy, from 8 KiB up: 1 MiB `Uint8List` 192 → 51 µs, `Float64List` 191 → 52–66 µs, peak memory 4× → 2× (AOT, macOS). Needs regenerating with the matching nitro_generator.
- **Fix:** a `@zeroCopy` typed-data return that was the result of `Isolate.run`/`compute` pointed at freed memory. Needs regenerating.
- **Fix:** a record string field that starts with U+FEFF kept losing it on decode (Dart and Swift).
- **Perf:** an ASCII string field decodes 3× faster and encodes 30% faster; `List<int>`/`List<double>`/`List<bool>` fields encode 2.7× faster and decode 1.3–1.9× faster.
- New `RecordReader.fromNative(ptr, adopt:)`, `readBlobView()`, `RecordReader.keptAlive`, `RecordReader.lendMinBytes` (8 KiB), `writeIntList`/`writeDoubleList`/`writeBoolList`, `readIntList`/`readDoubleList`/`readBoolList`.

nitro_generator:

- **Perf:** typed-data fields of a `@HybridRecord` reach Dart without the Dart-side copy. Needs the matching nitro.
- **Perf (C++):** a record or variant is built in the block Dart receives, one copy fewer per return.
- **Perf (C++):** `List<int>`/`List<double>` fields are one copy each way (5–9× faster); `List<bool>` encodes 3× faster; typed data is read without a zero-fill pass.
- **Perf (Kotlin):** records encode into a stream they fill directly (scalar records 3× and lists of records 5× faster on ART); typed-list fields are written in bulk (9–16×); primitive lists are 5× faster to write and 9× to read; short ASCII strings are written and read without the UTF-8 codec (`List<String>` 4× faster to write, 2× to read); records decode from the byte array, not through `ByteBuffer` accessors (scalar records and lists of records 2× faster to read).
- **Perf (Swift):** the writer hands its block to Dart instead of copying it (small records 3–4× faster to encode); `List<int>`/`List<double>` 30× faster to write and 10× to read, `List<bool>` 20×; typed arrays, strings and `Data` copied once.
- **Perf (Dart maps):** decoded in place; record and variant values no longer allocate per entry.
- **Changed (hand-written Swift):** `NitroRecordWriter.toNative()` empties the writer, and `bytes` is a read-only copy.
- **Fix (Kotlin):** a record with a `String?`, a nullable typed list or a nullable `List` field did not compile.
- New gates: `tool/verify_record_wire.dart` (C++/Swift/Kotlin codecs against Dart's bytes) and `tool/verify_record_lend.dart`. `verify_cpp_bridge_compiles.dart` now fails its CI step on a compile error (it returned the result from `main`, which Dart ignores).
- **Breaking (hand-written C++):** `NitroRecordWriter::_buf` is gone and the writer is not copyable; read the payload with `toBuffer()`. Regenerated plugins can be linked next to ones generated earlier.
