# Migrating to 0.7.1 — nullable struct fields and nullable map values

0.7.1 is a patch release. **Regenerate** (`nitrogen generate && nitrogen link`)
so generated code and the runtime come from the same toolchain — the web
`@HybridStruct` layout changed, and structs with nullable scalar fields gain a
synthesized companion field.

Nothing you already had compiles differently. Everything below is either newly
allowed or a fix for something that did not work.

## `@HybridStruct` fields may now be nullable

A flat C struct carries absence two ways, chosen automatically by the field
type:

| Field kind | Absence encoded as |
|---|---|
| `String?`, TypedData, nested `@HybridStruct?` | `nullptr` (the slot is already a pointer) |
| `int?`, `double?`, `bool?`, `DateTime?`, `@HybridEnum?` | a synthesized `int8_t <field>HasValue` byte after the value slot |

```dart
@HybridStruct()
class Reading {
  final double? temperature;   // int8_t temperatureHasValue follows it in C
  final String? label;         // const char*, nullptr when absent
  final int sequence;          // unchanged
  const Reading({this.temperature, this.label, required this.sequence});
}
```

This mirrors the `NitroOptInt64` / `NitroOptFloat64` / `NitroOptBool` wrappers
already used for nullable primitive **parameters**, and the synthesized
`<field>Length` already used for TypedData fields.

**What changes for you:**

* A struct with **no** nullable scalar fields is byte-identical to 0.7.0 — no
  ABI change, nothing to do.
* A struct that gains a nullable scalar field gets an extra byte per such
  field in the C typedef. Native implementations written against the generated
  header pick this up on regeneration.
* On Kotlin the field is `Long?` / `Double?` / `Boolean?`; on Swift it is an
  Optional on the public struct. Both are handled by the generated bridge.

Previously these fields passed validation but generated code that did not
compile (a `String?` field was assigned straight into a `Pointer<Utf8>`, and
emitted no `nativeFree`, leaking the string). `DateTime` struct fields were
broken in the same way, nullable or not, and now encode as ms-epoch.

## `Map<String, T?>` values may now be null

`int?`, `double?`, `bool?` and `String?` map values round-trip on every
backend. The String-key map wire already tags each value, so null is simply
tag `0` — no layout change, and non-nullable maps are byte-identical.

```dart
Map<String, int?> echoCounts(Map<String, int?> value);
```

The **key stays present** with a null value; it is not dropped.

Two cases are still rejected, with **E018**:

* an int-keyed map (`Map<int, T?>`) — its values carry no type tag, so there is
  nowhere to record null;
* an enum, `@HybridRecord` or `@NitroVariant` value — Swift decodes those
  through `compactMapValues`, which drops a nil entry rather than keeping the
  key.

Use `NitroAnyMap` for those: its wire format tags every value and already
carries nulls.

## New validator errors

| Code | Meaning | Fix |
|---|---|---|
| `E018` | Nullable map value the wire cannot carry | Use `NitroAnyMap`, or a non-nullable value type |
| `E020` | Two `@HybridEnum` cases share a native value | Give every case a distinct value |

`E020` catches a silent corruption: the wire carries the number, so one of the
colliding cases could never be decoded, and the generated code contained
duplicate Dart switch cases and an invalid Swift enum.

## Web `@HybridStruct` fields

`String`, TypedData and nested struct fields now work in a web-targeting
struct — they are pointer slots in the wasm32 layout. `E017` now only rejects
record, variant and map fields.

**This changes the web struct layout**, which is why regeneration is required.

## Runtime fixes worth knowing

These need no code change on your side, but they alter behaviour you may have
worked around:

* A worker isolate whose reply could not be sent used to die and leave every
  call dispatched to it pending **forever** (there is no timeout). The pool now
  fails those calls.
* A failed `loadWebModule` stayed cached, so every retry replayed the same
  rejection. Retries now work.
* `RecordReader` rejects a corrupt length prefix instead of building a view
  past the allocation.
* `readCString` throws on an unterminated pointer instead of spinning.
