# Migrating to 0.6.0

## TL;DR

```bash
flutter pub upgrade
nitrogen generate && nitrogen link
```

`nitro` and `nitro_generator` must both be `0.6.0`. Generated code and the runtime
changed together, so regenerating is required — not optional.

## What changed

Synchronous bridge returns no longer allocate. For nullable primitives,
`@HybridStruct` returns and `String` returns, the native side now hands Dart a
pointer into a reusable per-thread buffer, and Dart no longer frees it.

`@nitroAsync` and `@nitroNativeAsync` are unchanged. They decode on a different
isolate thread (`Isolate.run`), where thread-local storage is a different slot,
so they keep their own heap allocation and free.

## Do I need to change my code?

**Dart callers: no.** The API is identical — `int?`, `String`, and struct returns
behave exactly as before.

**Plugin authors: no,** unless you hand-wrote a C bridge instead of generating it
(see below).

## If you mix versions

Upgrading one side without the other is the one thing that breaks:

| Situation | Result |
|---|---|
| Runtime 0.6.0 + code generated by 0.6.0 | correct |
| Runtime 0.5.x + code generated by 0.6.0 | compile error — `toDartStringBorrowed()` is missing |
| Runtime 0.6.0 + code generated by 0.5.x | still allocates and frees; correct, but no gains |
| Generated Dart 0.6.0 + stale native bridge | **crash** — Dart no longer frees, native still allocates |

The last row is why `nitrogen link` matters: it syncs the regenerated bridge into
the iOS/macOS/Android targets. Symptom is an abort inside `<lib>_nitro_free`
(`pointer being freed was not allocated`, or `Scudo: misaligned pointer` on
Android).

## Hand-written C bridges

If you return borrowed memory from a sync function, Dart will not free it. If you
return owned memory (`malloc`/`strdup`), it will leak — Dart no longer releases
sync returns. Return a pointer into per-thread storage, or copy into it and free
your buffer before returning:

```cpp
static thread_local std::string _g_str_ret;

const char* my_lib_get_name(int64_t instanceId, NitroError* err) {
    _g_str_ret = compute_name();          // reuses capacity — no allocation when warm
    return _g_str_ret.c_str();            // valid until the next such call on this thread
}
```

The value must be decoded immediately after the call returns, which the generated
Dart does. Never use this for `@nitroAsync` / `@nitroNativeAsync`.

Binary payloads (`@NitroResult`, `@NitroVariant`, records, maps, lists) are
unaffected — they were never NUL-terminated strings and keep their existing
ownership.

## New in 0.6.0

- `<Class>_createNativeInstance([String key])` takes an optional key, creating an
  independent native instance per key. The default key returns the shared
  singleton, so existing calls are unaffected.
- `NitroCoalescer` batches concurrent `@nitroNativeAsync` completions over one
  port. Opt-in; see the `nitro` README.

## Performance

Measured on an M1 Pro. Sync returns only.

| Path | Before | After |
|---|---|---|
| nullable primitive | 15.0 ns | 0.2 ns |
| struct return | 16.1 ns | 1.0 ns |
| string return (32 B) | 27.8 ns | 9.9 ns |
| instance lookup, 4 live instances | 10.0 ns | 1.3 ns |
| instance lookup, 4 threads | 26.1 ns | 0.5 ns |

Reproduce with the harnesses in `benchmark/tool/` (build with
`-fno-builtin-malloc -fno-builtin-free`, or the compiler elides the very
allocation being measured).
