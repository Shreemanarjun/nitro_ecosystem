# Migrating to 0.7.0 — Web (WASM) support

0.7.0 adds a full web target: the same C++ implementation that backs your
native platforms is compiled to WebAssembly with Emscripten and driven by a
generated `dart:js_interop` bridge. The binary wire format, the `NitroError`
out-param protocol, streams, and `@nitroNativeAsync` all work on web — under
both `flutter build web` (dart2js) and `flutter build web --wasm` (dart2wasm).

Nothing changes for plugins that do not target web, **except**: regenerate
(`nitrogen generate && nitrogen link`) so generated code and the runtime come
from the same toolchain, as with every nitro upgrade.

## Adding web to a plugin

1. Add the target to your spec and regenerate:

   ```dart
   @NitroModule(
     lib: 'my_plugin',
     ios: AppleNativeImpl.cpp,
     android: AndroidNativeImpl.cpp,
     web: WebNativeImpl.wasm,     // ← new
   )
   ```

2. Run `nitrogen link`. It writes `web/build_web.sh` (the Emscripten build),
   creates `assets/web/`, and copies `nitro_wasm_compat.h` into `src/native/`.

3. Declare the artifacts and the web plugin entry in `pubspec.yaml`
   (`nitrogen init --platforms=...,web` scaffolds all of this for new plugins):

   ```yaml
   flutter:
     plugin:
       platforms:
         web:
           pluginClass: MyPluginWebPlugin
           fileName: my_plugin_web.dart
     assets:
       - assets/web/
   ```

4. Build the module: `bash web/build_web.sh` (needs the
   [Emscripten SDK](https://emscripten.org) on PATH).

5. Switch the spec's singleton to the platform factory. For a web-targeting
   spec, the generated layout splits: the dart:ffi implementation moves out of
   the `.g.dart` part into `generated/native/<file>.ffi.g.dart`, so
   `_MyPluginImpl()` no longer exists in the part. Use the generated
   platform shim instead:

   ```dart
   import 'my_plugin.platform.g.dart';
   ...
   static final MyPlugin instance = createMyPluginInstance();
   ```

6. On web, module instantiation is asynchronous — await the generated
   `ensureMyPluginReady()` before first use (it is a no-op on native, so call
   it unconditionally in `main()`).

## The C++ implementation on web

- **No threads.** The browser module is single-threaded: constructing a
  `std::thread` aborts at instantiation. Guard worker threads with
  `#ifndef __EMSCRIPTEN__` and run tasks inline (completions still reach Dart
  asynchronously — delivery is microtask-deferred), or use
  `emscripten_set_interval` for periodic work such as stream emitters.
- **Include seam.** Where your impl includes `dart_api_dl.h`, use:

  ```c
  #ifdef __EMSCRIPTEN__
  #include "nitro_wasm_compat.h"
  #else
  #include "dart_api_dl.h"
  #endif
  ```

  Every existing `Dart_PostCObject_DL` call site then compiles unchanged —
  the shim reroutes posts through the module callback the Dart runtime
  registers at load.
- **Exceptions stay on.** The build script compiles with `-fwasm-exceptions`;
  the `try/catch → NitroError` contract is identical to native.

## Web semantics to know

| Topic | On web |
| --- | --- |
| `@nitroAsync` | Runs inline on the main thread (browsers have no isolates) — prefer `@nitroNativeAsync` for real async work (W008 warns) |
| `@zeroCopy` | One bulk copy (snapshot) — heap views detach when module memory grows (W009 warns) |
| `int` | 53-bit fidelity under dart2js (JS numbers); exact under dart2wasm |
| `@HybridStruct` | Prim/enum/bool/DateTime fields only for now (E017 errors otherwise — use `@HybridRecord` for full type support) |
| `NativeHandle` / `Pointer` | The address is a wasm linear-memory offset; overrides are typed `dynamic` because the classes differ per platform |
| Sync borrowed returns | Same contract as native: strings and nullable primitives are borrowed; framed blobs are owned and freed |

## Removed / moved API (runtime)

- `NitroNullableInt/Double/Bool.fromNative` (statics) → top-level
  `nitroNullable{Int,Double,Bool}FromNative` in the native branch.
- `NitroAnyMap.fromNative` / `.toNative` → `nitroAnyMapFromNative` /
  `NitroAnyMapNative.toNative` extension; the pure entry points are
  `NitroAnyMap.readFrom` / `writeTo`.
- The default log sink is now zone-aware `print` (was Flutter's `debugPrint`)
  so `package:nitro`'s import graph is flutter-free and compiles under plain
  `dart compile js/wasm`. Override `NitroConfig.instance.logHandler` to keep
  `debugPrint` throttling.
- W007 (streams/native-async unsupported on web) is retired; W008/W009/E017
  are the new web-specific checks.

For custom `@NitroCustomType` codecs on web, implement the platform-neutral
`NitroWireCodec<T>` (byte-offset based) alongside — or instead of — the
native-only `NitroFfiCodec<T>`.
